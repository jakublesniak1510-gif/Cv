# Przelewy24 obok Stripe – instrukcja uruchomienia

Klient w kasie wybiera: **BLIK / karta / Apple Pay / Google Pay** (Stripe, domyślnie) albo **Przelewy24 (przelew online, BLIK)**.
Karnety i paczki kodów dla instytucji nadal płaci się tylko przez Stripe. Kluczy nie wpisujemy do repozytorium ani do czatu – tylko w Render.

## 1. Dane z panelu Przelewy24

Panel P24 → **Moje dane → Dane do API i konfiguracji modułów** (w sandboxie ten sam ekran na sandbox.przelewy24.pl):

| Zmienna w Render | Gdzie w panelu P24 |
|---|---|
| `P24_MERCHANT_ID` | ID sprzedawcy (Merchant ID) |
| `P24_POS_ID` | ID punktu sprzedaży (POS ID) – zwykle takie samo jak ID sprzedawcy |
| `P24_CRC` | Klucz do CRC |
| `P24_API_KEY` | Klucz do raportów / klucz API (REST) |

Konto testowe (sandbox) ma **inne** ID sprzedawcy i klucze niż produkcyjne – zakłada się je w P24 osobno (formularz „konto testowe” / sandbox).
ID z sandboxu użyte na produkcji (`secure.przelewy24.pl`) kończy się błędem **„401 Incorrect authentication”**. Jak rozpoznać, które ID masz:
numer sprzedawcy widoczny na stronie płatności testowej (sandbox) to ID testowe – na produkcji musi być inny.

**Pole „Adres IP” w panelu P24 zostaw puste.** Render nie ma stałego adresu IP, więc ograniczenie po IP blokowałoby połączenia z serwisu.

## 2. Adresy do wpisania w panelu P24

- **Adres powiadomień (urlStatus):** `https://cvpodogloszenie.pl/api/p24/status`
  (serwis podaje go też automatycznie przy każdej transakcji; w panelu wpisz ten sam, jeśli P24 o niego prosi).
- **Adres powrotu (urlReturn):** podawany automatycznie przy transakcji – `https://cvpodogloszenie.pl/?id=<numer zamówienia>`. W panelu można wpisać `https://cvpodogloszenie.pl/`.
- Metody płatności (BLIK, przelewy, karty) włącz w panelu P24; wypłaty – na firmowy rachunek.

## 3. Kolejność: najpierw sandbox, potem produkcja

1. **Sandbox.** W Render ustaw dane z konta testowego oraz:
   - `P24_SANDBOX=1`
   - `PAY_PROVIDER=both` (Stripe zostaje włączony, P24 dochodzi jako druga opcja)
2. Zrób zamówienie testowe, wybierz w kasie „Przelewy24”, zapłać na stronie testowej P24 (np. kwotą 1 zł z kodem rabatowym albo najtańszym dodatkiem). Sprawdź, że:
   - po powrocie dokumenty się generują (status „opłacone”),
   - w panelu admina zamówienie ma płatność „przelewy24”; zwrot przez API w sandboxie zwykle kończy się 409 „Insufficient funds available” (puste saldo testowe – patrz pkt 5), więc wystarczy sprawdzić czytelny komunikat i przycisk **„Oznacz jako zwrócone”**,
   - w panelu admina widać żółty baner **„P24 sandbox”** – to przypomnienie, że wpłaty nie są prawdziwe.
3. **Produkcja.** Podmień w Render `P24_MERCHANT_ID`, `P24_POS_ID`, `P24_CRC`, `P24_API_KEY` na produkcyjne i **usuń `P24_SANDBOX`**. Zostaw `PAY_PROVIDER=both`.
4. Zrób jedną prawdziwą płatność na małą kwotę i zwrot (z panelu admina albo – przed rozliczeniem wpłaty – ręcznie w panelu P24 i „Oznacz jako zwrócone”, pkt 5).

## 4. Jak to działa (dla pewności)

- Wpłata jest potwierdzana tylko po weryfikacji w P24 (`verify`) i gdy kwota = cena zamówienia.
- Klient może przy ponownej płatności zmienić bramkę (np. porzucony P24 → Stripe); otwarta sesja Stripe jest zamykana, rezerwacje kodu i karnetu się nie dublują.
- Jeśli klient zapłaci przez P24 za zamówienie opłacone już przez Stripe, wpłata nie jest potwierdzana, a do właściciela idzie alert – zwróć ją w panelu P24.
- `PAY_PROVIDER=p24` – tylko Przelewy24; brak `PAY_PROVIDER` – tylko Stripe (gdy jest klucz Stripe).

## 5. Wnioski z uruchomienia (październik 2026)

Sandbox i produkcja przetestowane: rejestracja transakcji → płatność (BLIK) → powiadomienie → `verify` → dokumenty wygenerowane.

### Zwroty a saldo P24
- Przelewy24 robi zwrot **z salda wpłat na koncie P24**, zanim zostaną wypłacone na rachunek. Tuż po wpłacie (status transakcji „Dokonana”, jeszcze nie „Rozliczona”) albo po wypłacie całego salda P24 odpowiada **409 „Insufficient funds available”**.
- Panel admina pokazuje wtedy komunikat z instrukcją. Do wyboru:
  1. ustawić w panelu P24 **rezerwę na zwroty** w ustawieniach wypłat albo doładować saldo – wtedy przycisk **Zwrot** w panelu admina działa od razu;
  2. zrobić zwrot ręcznie w panelu P24 (**Transakcje → Zwrot**) albo przelewem, a potem w panelu admina kliknąć **„Oznacz jako zwrócone”** (zapisuje zwrot w zamówieniu i w sprzedaży, nie wysyła pieniędzy).
- Klientowi zawsze zwracamy **pełną zapłaconą kwotę** – prowizja P24 nie obciąża klienta.
- Ponowne kliknięcie **Zwrot** w ciągu 10 minut po próbie bez odpowiedzi najpierw sprawdza listę zwrotów w P24, więc ten sam zwrot nie zostanie zlecony dwa razy.

### Test dostępu do API (testAccess)
`GET /api/v1/testAccess` nie zwraca nagłówka `WWW-Authenticate`, więc przeglądarka **nie pokaże okna logowania** (zobaczysz tylko błąd 401). Sprawdzaj go z Basic auth `POS_ID:KLUCZ_API`, np.:

```bash
curl -u "POS_ID:KLUCZ_API" https://secure.przelewy24.pl/api/v1/testAccess
```

```powershell
$c = [Convert]::ToBase64String([Text.Encoding]::ASCII.GetBytes("POS_ID:KLUCZ_API"))
Invoke-RestMethod https://secure.przelewy24.pl/api/v1/testAccess -Headers @{ Authorization = "Basic $c" }
```

W sandboxie adres to `https://sandbox.przelewy24.pl/api/v1/testAccess`. Kluczy nie wklejaj do czatu ani do repozytorium – wpisuj je tylko w terminalu na swoim komputerze i w Render.

### Gdzie szukać błędów
Błędy płatności i zwrotów (z prawdziwym powodem odpowiedzi P24, bez kluczy i danych osobowych) są w panelu admina: **Problemy → Dziennik błędów**.
